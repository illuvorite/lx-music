## 1. 目标与边界

**目标**：把现有多源音乐播放器的界面，按 QQ 音乐桌面端的视觉与交互规整地重做一遍——外壳、侧栏、工具栏、首页、歌单、搜索、播放器、我的音乐、设置全部统一到同一套浅色设计语言，页面结构与交互习惯对齐 QQ 音乐。

**边界**
- 只做界面与交互；播放内核、解码、下载、同步、音源适配等底层逻辑不动。
- 只复刻版式与交互模式，**不使用任何第三方商标、LOGO、官方图片与文案**；图标自绘，文案用中性通用词。
- 本轮只做浅色；不新增第三方依赖。

## 3. 技术栈

- 运行时：Electron 40 + Vue 3.3（`<script setup>`）+ vue-router 4 + Less + CSS Modules + webpack 5。
- 图标：`svg-sprite-loader` + `src/renderer/assets/svgs/*.svg`（新增图标全部自绘）。
- 状态：自研 `BaseStore`（`store/*/state.ts` + `action.ts`）；持久化用主进程 SQLite worker。
- 样式分层：`assets/styles/index.less` 注入 `--qm-*` token → 各组件 CSS Module 只引用 token。
- 不加状态管理/UI 库，避免与现有骨架冲突。

## 4. 数据来源

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 首页推荐 / 歌单广场 / 歌单详情 / 榜单 / 搜索 | `musicSdk`（`tx`/`kw`/`kg`/`wy`/`mg`/`bd`） | 复用 `getAndSetList`、`getAndSetListDetail`、leaderboard action、`tipSearch`；**默认源由用户在设置里选**，不强制切换 |
| 我喜欢 / 自建歌单 / 播放历史 | 本地 SQLite | `loveList`、`userLists`、`playedList`；侧栏计数用 `getListMusics()` 回填（`allMusicList` 非响应式，需响应式承接） |
| 下载 / 本地文件 | 主进程下载模块 | 设置中关闭下载时，入口置灰并提示 |
| 歌词 / 封面 / 音质 | 在线源 + 本地缓存 | 沿用现有链路 |
| 收藏的歌单、已购 | 需新增本地表 | 阶段 ⑦ 实现（无则不显示该入口） |

### 播放失败自动换源（本需求新增）

1. 监听播放错误：`core/player` 的错误回调 / `window.app_event.on('error')`（`usePlayStatus.ts` 已有钩子）。
2. 判定可换源：仅当失败原因是「版权/无版权、付费、取流失败」且当前歌曲为在线歌曲，且本次播放未换过源（同一首歌一次播放最多尝试 2 个源，防止死循环）。
3. 找替代：用 歌名 + 歌手 在其余源搜索（复用 `musicSdk[source].musicSearch.search`），按「歌名完全一致 > 歌手一致 > 时长相近（±5s）」打分取最优。
4. 切换播放：`setPlayMusicInfo` / 播放列表索引替换后重播，并 Toast 提示 `已切换至 xxx 音源播放`。
5. 开关：新增设置项 `player.autoSwitchSource`（默认开），在「播放」设置分组中以复选框呈现。
6. 记录：把可用替代写入 `saveOtherSource`（已有换源缓存表），列表页右键「换源」也复用同一份数据。

## 5. 响应式适配

| 断点 | 侧栏 | 内容列数 | 说明 |
| --- | --- | --- | --- |
| `< 1100px` | 折叠 64px | 5 | 仅图标，悬浮展开提示 |
| `1100 – 1400px` | 214px | 6 | 默认窗口区间 |
| `1400 – 1700px` | 214px | 7 | 卡片自动放大 |
| `≥ 1700px` | 214px | 8 | 首屏封面加大，间距按 `--qm-s*` 升一档 |

- 全屏（F11）时内容内边距升一档、封面最小宽 160px。
- 窗口最小 1000×670；播放栏与工具栏高度固定，内容区独立滚动。
- 所有卡片网格使用 `auto-fill + minmax(150px, 1fr)`，不写死列数。

## 6. 实施顺序与验收标准

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| ① | `--qm-*` token 注入 + 通用组件（SongCard / SongRow / Chip / EmptyState / Skeleton / 滚动条） | 组件走查页可见全部状态；无硬编码色值残留（grep 校验） |
| ② | 首页推荐 | 1080×676 截图与规范逐项对齐；hover/点击/右键正常 |
| ③ | 歌单详情 | 头部信息、操作条、歌曲表、分页、双击播放、右键菜单全通 |
| ④ | 搜索页 | 历史/热搜/联想/结果分页/空态；键盘上下+回车可用 |
| ⑤ | 歌单广场 + 排行榜 | 标签筛选、排序、源切换、分页、榜单切换 |
| ⑥ | 播放器全屏页 + 队列/音质面板 | 歌词滚动、进度拖动、评论面板、Esc 退出 |
| ⑦ | 我的音乐（列表 / 下载 / 收藏歌单新表） | 列表增删改查、拖拽排序、导出导入、计数正确 |
| ⑧ | 设置页 + 通用弹层统一 | 9 个分组视觉统一；菜单/Toast/Modal 全站一致 |
| ⑨ | 响应式与回归 | 1000/1280/1600 三档宽 + 全屏；无布局溢出与文字截断异常 |

每阶段完成即：`npm run dev` 全量编译零报错 → 截图比对 → 记入 `docs/qq-music-todo.md`。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 改动面大导致功能回归 | 每阶段只动表现层；底层 store/IPC 不改签名；每阶段结束做一次全路径手动走查 |
| 源接口不稳定导致页面空 | 所有列表页保留骨架屏 + 空态 + 重试；默认源可切换并支持自动换源 |
| 非响应式数据（`allMusicList` 为 markRaw Map） | 统一用响应式承接层（侧栏计数已按此实现），新增代码遵循同一模式 |
| 样式散落难以收敛 | token 集中在 `index.less` 的 `--qm-*` 段；新增页面禁止直接写色值 |
| 商标/素材合规 | 自绘图标 + 中性文案；不引入官方图片与字体 |
